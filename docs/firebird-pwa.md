# Firebird PWA：当前路线

[English](firebird-pwa.en.md) · 2026-11-14，Europe/London。

## 需求变更

用户明确要求推倒原独立 CAS，直接移植 Firebird 并打包本机镜像、扫码安装；随后允许大幅修改、删除不再需要的内容。因此，旧文档中的“不运行 Firebird / TI OS / 不打包镜像 / 自制全部 LCD 资产”不再是当前产品约束。仍保持本机离线计算、原始镜像保护、手机/桌面同一核心，以及如实验收边界。

## 实际实现

| 层 | 当前入口与职责 |
| --- | --- |
| 模拟核心 | `third_party/firebird/core/`，固定上游提交 `ccd0d1dfa1cf87133e2dea44c482d648d99a789b`，GPLv3 |
| WASM 适配 | `tools/firebird/bridge.cpp`，复用真实 ARM/Thumb 解释器、NAND、外设、LCD、键盘与快照；不编译 Qt/GIF/JIT |
| 编译 | `tools/build-firebird.py`，Emscripten 3.1.74；32 MiB 初始、512 MiB WASM 上限，允许增长 |
| 用户界面 | Vue 3.5.44；`src/firebird/App.vue`、`Keypad.vue`，320×240 真实 RGB565 framebuffer 转 RGBA Canvas |
| 运算 | `src/firebird/worker.js`，独立 Worker 本机运行 TI 系统；无服务端计算、运行时 CDN 或原生模拟器依赖 |
| 存档 | 独立 IndexedDB；根路径名 `gaculator-firebird` 不变，项目路径另设命名空间；快照包含 RAM、外设和 NAND 改动；有改动且输入空闲后自动保存；隐藏时先补齐改动再暂停 |
| 分发 | Vite 6.4.5、qrcode 1.5.4、完整版本化缓存；`tools/serve.mjs` 只分发 `temp/firebird-dist/` |

上游旧 Emscripten Makefile 没有直接拿来构建：它缺少当前 C++ keypad/CX II 源文件。适配器改为手动步进、浏览器时间预算和 100 Hz 虚拟节拍；计算不阻塞页面主线程。无原生 JIT，性能不能照搬桌面 Firebird。

上游改动：Emscripten 分支的退出使用 abort 避免关闭 assert 后未定义返回；补齐 OS 头文件；NAND 映射后关闭输入文件、释放 MEMFS 大缓冲；修复 `flash_suspend` 写失败错误返回成功。GIF 录制未提供。对应修改和重建脚本在随附 `source.zip` 中。

LCD 按实际核心输出，字体、菜单与 CAS 来自所运行的 OS。前景检测到背光关闭时触发电源唤醒中断，不额外合成 Home 键；隐藏时保存并暂停 Worker。长时间闲置自动唤醒仍需真实浏览器持续验证，不能仅由代码推断验收通过。

## 镜像与存储保护

- 仅打包指定 **CX CAS 4.5.2.8**：Boot1 524,288 字节、NAND 138,412,032 字节；原 `Snapshot` 不进入包。
- NAND SHA-256 固定为 `43a00d93c97a06969bfcdefca1d7a0356256286c1cbc5e7109a9b0d7a126dc1e`，打包前验证。运行后再次验证原件相同。
- 两份输入 gzip 后共 **19,726,938 字节**。`device.json` 保存压缩/原始大小与 SHA-256、WASM 身份；Worker 核验下载字节后解压。
- 原文件仅读取；运行时写入独立内存 NAND，持久化为浏览器快照。完整分发包包含 NAND，可能含原有或已删除文档的残留；用户已明确授权将其随 `site/` 公开上传到 `m0no3van/gaculator`。对应源码 ZIP 不包含镜像。
- 快照以“核心 WASM + 镜像”身份绑定，版本不符时保留并拒绝自动覆盖。多窗口使用 Web Locks 防止同一存档被并发写入。
- 保存必须等 IndexedDB 事务完成才报告成功。保存队列不丢弃排在其后的按键；失败保留上一次已提交存档。浏览器强制终止/配额回收仍可能损失未保存的最近输入。
- 当前主界面保留 LCD 和键盘；顶部保存/备份/安装/二维码等工具栏已移除。屏幕右上角“⋯”及设置弹窗已按用户要求移除；仅长按 ON 进入原生重载确认。首次加载显示缓存/启动状态。事务自动保存保留：前景仅在有输入改动、空闲至少 2 秒且距上次自动保存至少 30 秒后执行；触控接触期间推迟；切后台立即补齐未保存的改动，已有完整存档且没有新改动时复用它；目前没有可见的备份导出/导入 UI，也未实现跨核心版本快照迁移。原浏览器数据库未删除，旧独立 CAS 的 JSON 不迁入模拟器。

## 编译和本地访问

```powershell
npm ci
npm run build:firebird -- --emcc <Emscripten-3.1.74目录>/emcc.py
npm run build
npm run serve
```

已生成核心时不必每次重编。可用 `EMCC` 指定 emcc.py，用 `GACULATOR_DEVICE_DIR` 指定包含同名输入的目录。默认镜像路径为 `D:/01-Software/VirtualMachines/Calculator`。编译器/缓存/派生文件在 `temp/`；`npm run build` 从明确允许的资源准备 `temp/firebird-public/`，不会把旧 Pyodide/MathLive/字体打包进去。

服务器默认仅监听 `127.0.0.1:4173`，可用 `PORT` 换端口。浏览器 QA 使用独立端口 4186，避免覆盖旧来源的缓存/文档。此时旧独立 CAS 的 IndexedDB 仍保留。

现在本地试用可直接 `npm start`，在电脑浏览器打开 `http://localhost:4173/`，无需安装证书。`npm run pages:package` 在本机生成包含发布流程的静态 ZIP；完整步骤见 [Pages 发布](github-pages.md)。

## 手机扫码与安装

正式分发目标：用户计划后续使用 **GitHub Pages**。`github.io` 站点默认提供浏览器信任的 HTTPS，因此届时不再需要本机 CA、描述文件或电脑常开；二维码编码正式 HTTPS 网址，完整缓存后仍在手机本机离线运行。[GitHub 官方 HTTPS 说明](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https)

当前 `base: './'`、Manifest、Worker 资源和 Service Worker 使用相对路径，支持根站点及 `https://<user>.github.io/<repo>/` 项目站点。缓存、数据库与写入锁按项目路径隔离，保留根路径原数据库；不会删除其他项目缓存或旧独立 CAS 数据。换网址不会自动搬迁存档。

已配置 `npm run pages:package`：仅从生产资源白名单生成 `temp/gaculator-github-pages.zip`，内含 `site/`、发布工作流、SHA-256 清单与核验脚本；GitHub 上不需要镜像输入路径或编译器。用户已明确授权向公开仓库 `m0no3van/gaculator` 推送源码及完整 NAND 运行包，排除私钥、原 Snapshot 与浏览器存档。部署状态以 GitHub Actions 为准。使用方法见 [Pages 发布](github-pages.md)。以下本机证书方案保留为可选局域网测试，不用于正式 Pages 分发。

用户已明确确认向当前可信局域网分发。运行 `npm run lan` 使用本机已安装的 OpenSSL，在 `temp/firebird-certs/` 生成 CA 和服务器证书；HTTP 4187 提供手机安装说明、公开 CA/Apple 描述文件，HTTPS 8443 提供应用。二维码在 `temp/qa/firebird/install-qr.png`；可用 `GACULATOR_LAN_ADDRESS` 指定实际可达 IPv4。证书链/IP 会先自检，私钥不由任何 HTTP 路由分发，也不进入源码包。电脑/手机的系统信任仍由用户手动设置。

已有手机信任的 LAN 证书时，也可直接运行：

```powershell
$env:GACULATOR_HOST = '0.0.0.0'
$env:GACULATOR_CERT = 'D:/path/to/trusted-lan-cert.pem'
$env:GACULATOR_KEY = 'D:/path/to/trusted-lan-key.pem'
npm run serve
```

必须使用证书覆盖且手机信任的实际地址；多网卡地址用 `GACULATOR_LAN_ADDRESS` 更正。Android 使用浏览器安装功能，iOS Safari 使用“分享 → 添加到主屏幕”。首次先完成全部资源离线缓存，再启动 Worker，避免缓存安装与模拟器重复下载约 20 MB 的压缩镜像；之后使用本地缓存，但每次仍需校验、解压和初始化。缓存失败/超时会报告，允许在线启动，不宣称此时已经可以离线。首次应保持联网完成启动、安装，再按下文断网冷启动验收。

普通 LAN HTTP 不满足手机安全上下文/Web Locks/Service Worker；二维码不会安装根证书，应用不能静默安装 PWA。没有自有可信域名证书时，用户须在手机上完成证书信任设置。未设置公网隧道、未上传镜像、未修改系统信任。

完整安装验收：关闭电脑，手机飞行模式，彻底关闭应用，从安装图标冷启动，完成新 CAS 运算、保存、重开，并验证图形/文档。已运行 OS 自带功能不等于这些路径都通过验收。

## 验证与剩余限制

已通过：JS/Python 回归测试、生产构建、发布包核验及本地项目子路径分发检查；真实 WASM 冷启动/数学/存档恢复沿用此前验证；`npm run test:touchpad` 在真实 TI 图形页检查接触移动后 LCD 内的原生光标向右移动、抬手释放，覆盖从 GUI 手势到 Worker 输入处理的同一模块。原始 NAND 与 WASM 二进制未改动，现有存档身份不变。本次在独立 4193/4194 端口验证 402×874、390×664、320×568、874×402 与桌面布局，整页无溢出；停掉本地服务器后重载仍显示离线资源就绪并加载模拟器。这是桌面浏览器视口验证，不能代替真机；实际发布状态以对应提交的 GitHub Actions 为准；真实 iPhone 视觉/震感/断网冷启动未验收。报告见 `temp/qa/firebird/` 和 `temp/qa/delivery-check.json`。

## 缓存、手机布局与卸载清理

- 手机竖屏用动态可视高度 `100dvh` 和安全区分配 LCD/完整键盘；键盘纵向尺寸随剩余高度调整，页面禁止溢出与滚动回弹。横屏保留左右排列；高度不超过 600 CSS 像素时，外边距、间隔和 LCD 内边距收紧至 6 像素，仍保留实测安全区。Canvas 本身保持 4:3，在屏幕容器内水平、垂直居中，以宽高两项约束允许的最大尺寸显示，不裁掉 framebuffer。Safari 的浏览器工具栏由系统控制，主屏幕 standalone 可用空间更大。
- 缓存完成后，同一网址的后续启动无需重复下载镜像；保存过快照时沿用原恢复路径。设备解压、约 331 MB 的 WASM 初始化及 TI 系统运行仍耗时，不保证秒开；存储被系统回收后需重新联网缓存。更新不会删除 IndexedDB 存档。
- 长按 ON 的重载清理必须明确确认永久删除；停止 Worker/自动保存、等待在途存储写入、关闭数据库，持有本项目会话锁时注销相同 scope 的 Service Worker，等待安装中的缓存任务结束，删除本项目所有版本缓存与当前 Firebird 存档库。失败显示错误，可重试；旧独立 CAS、其他项目数据库和缓存不删除。
- 网页不能可靠监听卸载；删除主屏幕图标不等于确认浏览器数据零残留。[W3C Manifest 讨论](https://lists.w3.org/Archives/Public/public-webapps-github/2026Jul/0522.html)说明这一限制。应用内不再提供独立清理菜单；需彻底卸载数据时，删除图标后在系统网站数据设置中删除站点。Safari 副本可能使用不同存储，需另在“设置 → App → Safari → 高级 → 网站数据”删除相应站点。系统清理可能影响同域名其他项目，参见 [Apple 清理说明](https://support.apple.com/en-us/105082)。应用清理不声称擦除系统 HTTP 缓存、浏览历史或其他独立存储空间；需要零站点残留时用系统网站数据清理。

## 启动自动更新

每次页面启动先取得本项目会话锁，再限时绕过 HTTP 缓存检查服务器的 Service Worker。构建内容指纹作为版本标识，页面也记录对应构建。没有新版、检查超时、离线或下载失败时，继续使用完整的当前缓存。首次没有可用缓存时，仍须联网完成初次安装。

新版本逐项校验 SHA-256；已有缓存内容符合新清单时直接复用，界面更新无需重复下载相同 NAND/WASM。只有完整的新缓存才可激活，并在模拟器启动前自动重载；已经进入计算会话后不会因后台下载完成而强制重载。普通更新保留 IndexedDB 存档，核心/设备身份校验继续生效。其他窗口正在运行时，会话锁阻止抢占正在使用的模拟器。

首次从旧版升级到这套机制，须等“更新就绪”后关闭全部同站点窗口再打开一次。此后页面启动自动检查并切换完整新版。原生 PWA 的真机安装、离线冷启动与更新行为仍须 iPhone 验收。

## iOS 安装态尺寸与重复输入

用户截图的底部空白与 [WebKit 313800](https://bugs.webkit.org/show_bug.cgi?id=313800) 中报告的屏幕高 874、视口高 812、顶部安全区 62 的缺口相符；截图本身不能证明设备实际 API 值。`viewport.js` 只在 iOS `navigator.standalone`、未缩放、视口宽度与完整屏幕相符且缺失高度恰等于实测顶部安全区时，使用测量的屏幕高度修正根容器；其他浏览器、正常安装态、分屏与旋转保留正常视口规则。原安全区内边距仍保留；系统合成层若仍裁切，其保留区域不是 CSS 能保证消除的，须真机确认。

安装态键盘闪烁还涉及高度补偿的反馈循环：修正后 WebKit 可能交替报告缩短/完整高度。现在同一屏幕几何下保持补偿值，只在值真正改变时写入样式；分屏、窗口尺寸变化或旋转才重新判断。回归测试覆盖 812↔874 连续变化而不反复写入根高度。

重复字母来自按下已发送输入后，Safari 的零-detail 点击又被误判为辅助技术激活。现在追踪本次指针是否已提交，默认点击只消费同一次手势；不把零-detail 当作辅助激活的充分条件，也不使用会吞掉快速连按的时间防抖。键盘与辅助技术的无指针激活继续保留。DEL 等按键使用固定的可见边界；恢复的 Safari 震感控件缩至 1 像素、裁切且不参与指针命中，由可见标签的浏览器默认激活转发。按压反馈不移动触摸区域。指针捕获和实测边界检查防止拖动抬手或浏览器扩大命中范围时触发下面的书本键。

## 操作响应与键盘外观

模拟核心原本就是 C/C++ → WebAssembly；本次不改 ARM/Thumb 指令语义、WASM 二进制或存档身份。原 Worker 每次最多执行 8 ms 后固定再睡 16 ms；现在按 100 Hz 虚拟时钟与实际经过时间安排下一次运行，落后时立即让出后继续，领先才等待。恢复前重置计时基准，不补跑后台时长。空闲时按 30 FPS 检查 LCD，输入后 150 ms 内每次 CPU 步进都优先检查变化；主线程确认绘制前不再发送下一帧，避免画面消息积压。输入到达会取消原来的等待并立刻安排 Worker；逐 32 位像素比较后，仅发送变化画面，减少主线程绘制与数据搬运。

触摸按下立即提交输入，不再等抬手后的 click；键盘与辅助技术仍有激活路径。按压颜色跟随实际指针：匹配的抬手、取消、移出或捕获丢失立即清除，不再等待 90 ms 提示定时器或 70 ms CSS 颜色过渡；Safari 不依赖可能残留的 `:active`。90 ms 提示仅用于键盘/辅助激活。普通按键保持 4 个 guest tick、释放间隔 2 tick（40/20 ms 虚拟时间），替代 100/40 ms；修饰键先保持 4 tick，再按主键，修复 Shift/Ctrl 与主键同时入队时 OS 未识别组合的问题。`npm run test:keyboard` 用同一真实 NAND/快照比较快慢两种时长下 28 位重复/不同数字与积分/导数模板，忽略仅垂直光标闪烁的差异。Shift + 加号 = 积分，Shift + 减号 = 求导；加减上方仅显示统一常规字重的青色 `∫` / `d/dx`，移除箭头；电脑 Shift+小键盘加/减、Shift+减号也保留修饰键，普通键盘打出的 `+` 仍是加法。

`npm run test:performance` 在相同 WASM、相同恢复快照下测真实 Worker 调度，Node 嵌套定时器至少等待 4 ms。此电脑基线约 0.592× 虚拟实时速度、16 键排队 4201 ms；优化后约 1.005×、1016 ms。约 4.1 倍改善是**排队清空耗时**，不是所有运算加速倍数，也不是 iPhone 数据。两次约 6 秒运行的 WASM 步进耗时分别 440/455 ms，剩余差异主要来自调度与按键时长。报告在 `temp/qa/performance/`；基线脚本为修改前 Worker 的临时副本，不分发用户快照。

用户不接受上一轮按 [TI 官方 CX CAS 产品图](https://education.ti.com/en/products/calculators/graphing-calculators/ti-nspire-cx-cas?category=accessories) 改出的外观，本轮回滚到之前的平面配色、紫黑按键与青色副标；保留满屏、安全区、触控板功能及积分/求导标记。只回滚视觉样式，不撤销已验证的输入、缓存和存档修复。

本轮新增 `npm run test:latency`，使用同一真实 WASM/恢复状态、8 个数字/积分/导数输入，测 Worker 收到输入到首个数学字形变化画面的时间；不把竖直光标闪烁计作响应。同机配对样例中位数为 79.70 → 53.42 ms，最慢样例 104.18 → 82.83 ms；帧消息 50 → 13，传送字节 15,360,000 → 656,640（约减少 95.7%）。这是小样本桌面结果，不含 iPhone 触摸、Canvas 合成和物理屏幕刷新，不能宣称真机达到原生延迟。

变化帧只传首个变化像素所在行至最后变化行的整行区域（`bytes/y/height`），首次仍完整 320×240；前端按原坐标更新。回归测试重建完整 framebuffer 并逐字节核对，覆盖单像素、分离行和底行，不合成预测字形。JS/Python 回归检查通过；真实核心的按键/微积分/触控板检查沿用同一二进制。

延迟工具现扩展至 14 个场景，包括输入 `2` 后的 x²、幂、指数、三角与目录功能，并分开记录排队、核心执行与绘制耗时。本机桌面样本的 x² 首次字形响应约 41–55 ms，目录约 268–317 ms，后者包含明显的固件运行成本；未复现 x² 的长时间核心停顿。同步快照压缩另实测阻塞 Worker 约 1.4–2.2 秒，是间歇卡顿的实际来源。自动存档改为有输入改动且空闲才做，并跳过无新改动的重复压缩；压缩期间到来的输入保持脏状态，隐藏前会等待并补存最新一代。按压残留已按实际松手同步清除。已经开始的同步快照不能抢占，因此仍可能短暂阻塞；此次未改 WASM 或存档身份。这些测量不含 iPhone 触摸、浏览器合成或物理刷新，不能保证所有功能即时完成。真实 WASM 另验证便签板计算→Ctrl＋右→图形→Ctrl＋左→计算的页面切换。

## 长按 ON 确认重载

ON 按住至少五秒后松开，等待 500 ms 安静间隔，再调用 `window.confirm` 系统原生确认框；间隔内新的触摸、按键、失焦或切后台都会取消待弹确认。正文读取 `navigator.languages[0]`（缺失时用 `navigator.language`），中文区域使用中文，其他区域使用英文，不再中英并列。取消/确认按钮由系统浏览器语言决定；弹窗明确说明永久删除存档/缓存、约 20 MB 重新下载，以及没有个人存档的云端备份。达到五秒先尝试震动提示，松手后才弹出确认，避免同一次松开或 Enter 连发误确认；五秒内松开才发送一次普通 ON；长按不会提前触发 TI 关机。移出、取消触摸、另一根手指、失焦、切后台和卸载组件都会取消；聚焦 ON 后按住 Enter/空格提供同样的键盘操作。

取消确认不修改数据。确认后先对项目 HTML、离线脚本和 NAND 执行不经过离线 GET 缓存的 HEAD 联网预检；失败保留模拟器与数据并提示联网重试。通过后在会话锁内停止自动保存/Worker、等待在途保存结束、关闭数据库，复用项目范围清理，再导航到带一次性参数的项目 `index.html`。旧 Worker 即使暂时仍控制页面，缓存缺失也回退联网 HTML；重新安装缓存使用 `cache: reload`，离线脚本更新绕过 HTTP 缓存。其他项目及旧 CAS 数据不删除。

联网预检不等于完整包已重新下载；若清理后断网，须恢复网络再打开，已确认删除的个人存档无法从云端恢复。正常更新仍保留存档，重载清空不是普通更新的必需步骤。自动测试覆盖确认取消、离线保留、清理失败、存储写入等待、旧 Worker 重开回退，以及五秒阈值/取消/多指等手势。真 iPhone 上的长按、重下载与离线冷启动仍未验收。

## 触控板与按键反馈

中央确认键恢复原来的 13.2 个布局单位尺寸、位置与圆角。判定使用实时按键边界与浏览器实际点命中结果，按下和抬手都须落在同一个可见区域内；不会扩大触摸范围，圆角外的透明部分和空白处不确认。空白处仍可滑动，方向键、Ctrl/Shift 与键盘辅助激活继续保留。

原先 pointerdown/move 始终带 `down=true`，把滑动当作按住点击；还用 `event.buttons` 判断触摸移动，部分触摸事件可能被漏掉。现在 `touchpad.js` 区分 `contact` 与 `down`：接触/滑动不点击，6 CSS 像素内轻点才点击；Pointer Capture 接续板外抬手，取消/失焦/切后台解除接触。轻点按触控板方向/中央区域发送真实方向键或选择键，沿用 Ctrl/Shift 状态；便签板计算页用 Ctrl＋右方向键进入图形页，Ctrl＋左方向键返回计算页，沿用固件的前后页面导航。滑动继续发送真实触控板移动。Worker 按 guest tick 合并/分段移动，避免 `int8` 相对位移溢出；最终位置被处理后才释放；保存等待手势结束。

数字/字母、运算、控制、确认区在支持 Vibration API 的设备上分别使用 4 ms、8 ms、12 ms、双脉冲时序；中央选择键与方向键也调用控制区反馈。这是时序差异，不声称控制电机物理强度。按压颜色反馈保留，交互边界不移动。

ON 长按完成时先尝试 `[30, 40, 30]` ms 震动，再请求确认。[W3C 实现报告](https://w3c.github.io/vibration/reports/implementation.html)确认 WebKit 没有 Vibration API；五秒定时器不能生成可信开关点击，因此 iPhone PWA 不保证这个阈值震动，不用合成点击冒充。

Safari 功能检测到原生开关支持后，普通按键与触控板方向/中央区域使用固定可见标签，内含裁切为 1 像素且 `pointer-events: none` 的原生开关；不恢复覆盖整个按键的隐藏输入层。手指点击可见区域后由浏览器自身的标签激活转发，恢复系统轻触尝试，不调用 JavaScript `.click()`。[WebKit 说明](https://webkit.org/blog/15443/news-from-wwdc24-webkit-in-safari-18-beta/)和[原生开关实现](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/html/CheckboxInputType.cpp)说明单次轻触及可信用户事件限制。ON 保留普通按钮与长按确认流程。实际震感仍依赖设备、系统版本与设置，真 iPhone 尚未验收；五秒定时震动仍不能保证。

若必须在 iPhone 实现轻/中/重、不同纹理及连续触觉，应在保留同一离线 WASM 的前提下增加原生 WKWebView 壳，通过 [UIImpactFeedbackGenerator](https://developer.apple.com/documentation/uikit/uiimpactfeedbackgenerator) 或 Core Haptics 发出原生反馈。这涉及原生签名/安装，不属于本次 PWA 修改；没有为此引入依赖或伪装浏览器已具备该能力。

本机 Node v20.17.0 / Windows x64 连续步进的早期启动/恢复检查约 29–43 秒；实际耗时随机器负载和验证步骤变化，以报告为准。WASM 内存 **331,415,552 字节**，快照约 10 MB。此数字不是手机启动时间或内存总占用；解压与初始化峰值更高。

未验收：真实手机、证书安装、手机离线冷启动、持续闲置恢复、全部数学命令/图形/文档/USB 功能、屏幕阅读器的 OS 内部内容。Canvas 有名称和可访问硬件键盘，但 TI OS 不提供 DOM 文本辅助树。6.4 更新包不属于本次运行对象。
